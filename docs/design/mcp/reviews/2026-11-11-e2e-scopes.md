# End-to-end check: two scopes chosen at consent (2026-11-11)

Local Frontdoor (`DEV_LOGIN=true`, `BASE_DOMAIN=localhost`,
`FRONTEND_URL=http://localhost:3990`, throwaway database), real Chrome for
sign-in and consent, `curl` for the token exchange and `/mcp`. Credentials,
codes and tokens are omitted. ADR 0006, spec §4 rule 15.

| Step | Observed |
| --- | --- |
| `GET /.well-known/oauth-protected-resource/mcp` | `scopes_supported: ["frontdoor.read","frontdoor.preferences"]` |
| Consent page, client sends no scope | "It will be able to change" shows a checkbox for favourites, colour scheme and language, ticked, with the read-only hint |
| Untick, Connect | grant stored as `frontdoor.read`; audit `mcp.grant_created` with `["frontdoor.read"]` |
| Connect again, ticked | `/assistants`: "can change your preferences" |
| Connect again, unticked | same connection, now "read only" (scopes replaced, not a second grant) |
| Removing the owner-registered client | its connection disappears from `/assistants` |
| `curl`: approve keeping `frontdoor.read` → `POST /oauth/token` | `scope: "frontdoor.read"`, `expires_in: 600`; `tools/list` → `get_my_preferences`, `search_my_apps` |
| `curl`: approve keeping both → `POST /oauth/token` | `scope: "frontdoor.read frontdoor.preferences"`; `tools/list` adds `set_color_scheme`, `set_favorite_app`, `set_language` |

Found during the check:

- The accessibility tree named the checkbox "on". The label wrapped the input,
  but the checkbox now also has an explicit `aria-labelledby`. That change
  was built and linted; it was not re-checked in the browser.
- The first test client used the callback `http://127.0.0.1:8765`, copied from
  the 2026-11-03 check. In this browser that origin belonged to an unrelated
  local PWA, whose service worker answered the redirect. The page received one
  single-use code from this throwaway instance; the code expired after 60
  seconds. That client was removed, and the check was repeated on a port
  verified free (8799).
