# End-to-end check, local instance (2026-11-03)

Local Frontdoor (`DEV_LOGIN=true`, `FRONTEND_URL=http://localhost:3990`), real
Chrome for sign-in and consent, `curl` as the MCP client. Credentials and codes
are omitted.

| Step | Observed |
| --- | --- |
| MCP off | `GET /.well-known/oauth-authorization-server` → 404 |
| Owner turns it on, registers a client (`/assistants`) | client ID and secret shown once; secret not in later listings |
| `GET /oauth/authorize` | 302 to `/connect/<id>`, browser-bound cookie set |
| Consent page | shows owner label, return host, what is and is not shared |
| Approve | browser sent to `http://127.0.0.1:8765/callback?code=…&state=…&iss=http://localhost:3990` |
| `POST /oauth/token` (code + PKCE + resource) | 200, `Cache-Control: no-store`, `expires_in: 600`, refresh token |
| Same code again | `invalid_grant`; the grant is revoked, the token just issued → 401 on `/mcp` |
| New flow, `tools/list` as owner | 8 tools |
| `search_my_apps` | names, descriptions, Frontdoor launch links only |
| `get_app_access` | group names and counts only |
| `refresh_token` grant | new access and refresh tokens |
| Disconnect from `/assistants` | token → 401 at once |
| `GET /connect/x` headers | `X-Frame-Options: DENY`, CSP ends with `frame-ancestors 'none'` |
| `POST /mcp` with `Origin: https://evil.example` | 403 |
| Cancel on the consent page | redirect with `error=access_denied`, `state`, `iss`, no code |
| `client_id=nobody`, `redirect_uri=https://evil.example/cb` | Frontdoor error page, no redirect to the given URI |

Found and fixed during the check: the owner panel kept a stale connection
count after a disconnect, "1 active connections", and the consent page showed
a registered client's internal ID as its host.

Not covered here: a commercial assistant (Claude, ChatGPT, Copilot Studio)
against a public https deployment; to do on a staging instance before release.
